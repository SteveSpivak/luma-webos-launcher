## §0 LAWS (order of precedence: Laws > Gates > Style > Guidance)

| Law | Statement |
|-----|-----------|
| L1 | **NO INVENTING.** Every factual claim carries evidence: `file:line`, `commit:hash`, `url`, or `tool:output`. External claims carry citation: `source: URL/paper-id + section`. Unverifiable → label `[HYPOTHESIS]` or write `UNKNOWN — probe: <how>`. Guessing is a defect. |
| L2 | **WORK IS DONE ONLY WHEN ON GITHUB.** Committed atomically, pushed, PR merged or ready-for-review, CI green. Work that exists only in a container is LOST. |
| L3 | **ATOMIC COMMIT UNITS.** One commit = one logical change = one reviewable claim. If your message needs "and", split it. |
| L4 | **BLUF/ADHD/ASCII LAW.** See §4 below. |
| L5 | **NO SILENT FAILURES.** If a push fails, a scan fails, or you are blocked — record it and retry. Never drop work quietly. |
| L6 | **DOCS ARE MIRRORED, NOT HOARDED.** Every doc lives in the repo AND is hashed into the manifest (§5). A doc outside the manifest does not exist. |

## §4 STYLE LAW — BLUF / ADHD / ASCII (linted by docs-gate)

**S1** Every doc/PR/commit body starts with a TL;DR box (`> ⚡ **BLUF**`), ≤5 lines.
**S2** Inverted pyramid: conclusion → evidence → detail.
**S3** One idea per paragraph. Headers every ~100 words max.
**S4** ASCII diagrams are REQUIRED for architecture and flows — rules:
   - Only box-drawing + A-Z 0-9 -_/ characters
   - Max width 80 cols; all boxes aligned to 4-col grid
   - Every diagram gets: title line, legend if symbols used, and "see also" link
   - Example shape:
     ```text
     +-------------+        +-------------+
     |  agent-api  |  --->  |  work queue |
     +-------------+        +-------------+
              |                       |
              v                       v
         [evidence/]              [docs/ (mirrored)]
     ```
**S5** Three reading depths per doc: ⏱30s TL;DR → 📖3min → 🐢30min.
**S6** Tables/bullets over prose. Sentences ≤25 words. No wall of text >200 words
   without a header or diagram.

## §6 COUNCIL OF EXPERTS — REVIEW STRUCTURE

Reviews happen as PR reviews on GitHub — the PR thread IS the review record. Three review
roles, applied to every PR:

- **A. CORRECTNESS AUDITOR** — verify claims vs evidence; rerun 2+ random evidence artifacts.
  Any fabricated claim = hard "Request changes".
- **B. STRUCTURE/STYLE AUDITOR** — run docs-gate + review checklist (commit format, BLUF,
  ASCII diagrams, manifest, mirror sync).
- **C. SECURITY/PROVENANCE AUDITOR** — secret scan, dependency changes, citation validity
  (spot-check 2 external sources).

Verdict vocabulary: `APPROVE` | `APPROVE-WITH-NITS` | `REQUEST-CHANGES(blocking-defect)`.
Every REQUEST-CHANGES must cite the violated law/gate.
